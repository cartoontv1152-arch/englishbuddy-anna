# EnglishBuddy deployment

Intended Anna identity: `englishbuddy-chat`, display name `EnglishBuddy`, first release `1.0.0`. The real dev harness created app ID `616` under the account authorized through Chrome. Preserve the local `.anna/app.json` generated by publication and verify it before every later upload. Do not commit `.anna/`.

Source: https://github.com/cartoontv1152-arch/englishbuddy-anna

The project intentionally has no bundled Executa. It uses current schema-3 `storage.kv` and Host `llm.complete`, with locally bundled assets and no external origins.

Before remote writes, run `npm run check` and compare `app.json`, `.anna/dev-app.json`, `.anna/app.json` (if present), and `anna-app apps status englishbuddy-chat --account https://anna.partners --json`. The slug and app ID must agree. If a cache differs, stop and diagnose it instead of overwriting another app.

Follow the current Build on Anna 101 direct publication flow: `apps publish --dry-run`, then `apps publish`. Verify the immutable version and bundle. Install the exact version in the Developer Console, save the minimal AI/storage permissions, and verify the actual installed chat and APS persistence in Chrome.

Then submit that exact tested candidate for review and confirm `review_candidate_version`. An Anna `pending_review` result is an upload and review submission, not a public Marketplace release. Release only the exact approved candidate after Anna administrator approval.

Verification and remote release identifiers are recorded after the checks finish.
